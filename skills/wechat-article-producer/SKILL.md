# 公众号文章全流程 · wechat-article-producer

你现在进入**公众号文章生产模式**。从收集需求到推送草稿箱，全程由你主导，用户只需要确认关键节点。

---

## 🎯 核心流程（5 步）

```
用户触发 → [1.收集] → [2.写作] → [3.排版预览] → [4.确认] → [5.推送]
```

每一步完成后**必须等用户确认**再进入下一步。不要跳步。

---

## Step 1：收集需求（必做）

### 模式 A：用户指定主题
用户说"写一篇关于 XXX 的公众号文章"。

**你要做的**：
1. 确认主题和角度（"您想从哪个角度切入？"）
2. 确认目标读者（"这篇给谁看？行业内还是大众？"）
3. 确认篇幅（"大概多长？1500 字还是 2500 字？"）
4. 可选：问要不要从知识库里调用书本论据（business-advisor 的 24 本书）

**输出给用户确认的 brief**：
```
📋 写作 Brief
主题：XXX
角度：XXX
读者：XXX
篇幅：约 XXXX 字
风格：行业观察者 / 深度分析 / 轻松科普（根据 style.yaml）
参考：[如果调用了知识库，列出用到的书/框架]

确认开始写吗？
```

### 模式 B：从对话中提取
用户说"把刚才聊的整理成公众号文章"。

**你要做的**：
1. 回顾本次对话中用户表达过的**核心观点、判断、案例**
2. 整理成 3-5 个要点
3. 提出一个推荐标题和写作角度

**输出给用户确认的 brief**：
```
📋 从对话提取的写作 Brief
我从咱们刚才的对话里提炼了 X 个核心观点：
1. [观点1]
2. [观点2]
3. [观点3]

推荐标题：《XXX》
写作角度：XXX
预计篇幅：约 XXXX 字

您看要重点展开哪几个？标题要不要换？
```

**等用户确认后再进入 Step 2。**

---

## Step 2：写作

### 2.1 文章结构

按以下模板写 Markdown 文章（带 YAML front matter）：

```markdown
---
title: "文章标题"
author: "零碳电力圈"
summary: "一句话摘要，不超过 100 字"
---

[导语：1-2 段，点明为什么这个话题值得关注]

## 一、[第一个核心观点]
[展开论述，2-3 段]

## 二、[第二个核心观点]
[展开论述]

## 三、[第三个核心观点]
[展开论述]

## 写在最后
[收尾，给读者一个思考问题或行动建议]

---
*本文由「零碳电力圈」原创，欢迎转发分享。*
```

### 2.2 写作规则

1. **篇幅控制**：1500-2500 字（公众号最佳阅读区间）
2. **段落长度**：每段不超过 4 行（手机阅读体验）
3. **数据锚定**：每个核心观点至少有 1 个真实数据或案例支撑
4. **不编造**：不编造统计数字、政策条款、标准编号。不确定就说"据行业观察"
5. **语言风格**：参考 `~/.openclaw/skills/wewrite/style.yaml` 的 `tone` 和 `writing_persona` 配置
6. **互动容器**（可选，增强阅读体验）：
   - `:::callout info` — 蓝色信息框，用于补充说明
   - `:::callout warning` — 黄色警告框，用于重要提醒
   - `> 引用` — 用于引述专家/行业人士的话

### 2.3 知识库增强（可选）

如果文章涉及战略、管理、商业判断类话题，可以调用 business-advisor 知识库：
- qmd 会自动从 `~/.openclaw/workspace/经营管理知识库/` 检索相关书籍卡
- 把书本概念**自然地融入文章**，不要直接说"根据《创新者的窘境》"
- 例：用"破坏性创新"概念分析行业趋势时，嵌入概念但不点名书

### 2.4 输出

把完整的 Markdown 文章写入文件：
```bash
~/.openclaw/skills/wewrite/output/<日期>-<简短标题>.md
```

例如：`2026-04-06-AI重塑电力行业.md`

**写完后把文章核心内容发给用户看**（不是文件路径，是文章内容摘要 + 前 3 段），问：
```
文章写好了，全文约 XXXX 字。以上是前几段预览，您觉得：
1. ✅ 可以，直接排版推送
2. ✏️ 需要改（告诉我改哪里）
3. 🔄 推倒重来
```

## Step 3：排版 + 生成微信 HTML

用户确认文章内容 OK 后，执行排版：

```bash
cd ~/.openclaw/skills/wewrite
python3 publish_article.py output/<文件名>.md \
  --cover <封面图路径> \
  2>&1
```

### 封面图处理

**优先级**：
1. 用户提供了封面图 → 直接用
2. 有 AI 图片 API（config.yaml 里配了 image provider）→ 调用生成
3. 都没有 → 告诉用户"需要一张封面图，您可以：(a) 发一张给我 (b) 我用默认模板生成"

### 主题

默认使用 `wechat-tech` 主题（绿色左边框 + 蓝色引用 + 黄色高亮）。
如果用户有偏好（"用少数派风格"），可以切换主题。

---

## Step 4：推送到草稿箱

`publish_article.py` 会自动完成以下操作：
1. 解析 front matter（标题/作者/摘要）
2. Markdown → 微信兼容 HTML（wechat-tech 内联样式）
3. 获取微信 access_token
4. 上传封面图
5. 创建草稿

**推送成功后告诉用户**：
```
✅ 已推送到公众号「总得用AI干点什么吧」的草稿箱！

📝 标题：XXX
👤 作者：零碳电力圈
🎨 主题：wechat-tech

👉 登录 mp.weixin.qq.com → 内容管理 → 草稿箱 查看
   检查一下排版和配图，满意就可以发布了。
```

**推送失败时**：
- `40164 invalid ip` → "IP 白名单需要更新，请到微信开发者平台添加当前 IP"
- `access_token expired` → "Token 过期了，我重新获取一下"（自动重试）
- 其他错误 → 显示错误码，建议用户检查 config.yaml 的 appid/secret

---

## Step 5：后续操作（可选）

推送成功后，用户可能说：
- "再写一篇" → 回到 Step 1
- "改一下标题" → 修改 front matter → 重新推送
- "换个主题排版" → 重新跑 Step 3
- "删掉草稿箱里的" → 提示用户去公众号后台手动删除（API 不支持删草稿）

---

## ⚠️ 重要约束

### 不编造
- 不编造数据、政策编号、标准条款、企业名称
- 不确定的信息用"据行业观察"、"有分析认为"等模糊表达
- 参考 business-advisor skill 的反幻觉铁律

### 不替用户决策
- 每个关键节点（选题、文章内容、排版、推送）都要**等用户确认**
- 不要自作主张推送——"推到草稿箱吗？"必须等用户说"推"

### 文件路径
- 文章输出目录：`~/.openclaw/skills/wewrite/output/`
- 推送脚本：`~/.openclaw/skills/wewrite/publish_article.py`
- 样式转换器：`~/.openclaw/skills/wewrite/wechat_tech_converter.py`
- 微信配置：`~/.openclaw/skills/wewrite/config.yaml`
- 风格配置：`~/.openclaw/skills/wewrite/style.yaml`

### 首次使用引导（客户 Onboarding）

如果检测到 `config.yaml` 不存在或 `wechat.appid` 为空，进入**引导模式**：

```
看起来还没配置公众号信息，我来帮您设置。需要 2 样东西：

1️⃣ 公众号的 AppID 和 AppSecret
   获取方式：
   ① 打开 developers.weixin.qq.com（微信开发者平台）
   ② 登录后点击"公众号"→ 选择你的公众号
   ③ 在"基础信息"页面找到 AppID
   ④ 在"开发密钥"区域点"启用"或"重置"获取 AppSecret
      ⚠️ AppSecret 只显示一次，请立即复制保存！

2️⃣ IP 白名单
   在同一页面的"API IP白名单"里，添加你当前的公网 IP。
   不知道 IP？我帮你查：[执行 curl ifconfig.me]

拿到 AppID 和 AppSecret 后发给我，我帮你配好。
```
